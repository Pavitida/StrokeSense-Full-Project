# Data handling and retention

- Processing consent is required in the UI and independently in the API.
- Research consent is a separate, disabled option. The UI/API never call `save_fusion_sample`; there is no research collection endpoint.
- Camera/microphone input is uploaded to the local Streamlit session when captured, then to the local authenticated API only when Analyze is pressed. No third-party AI service receives it.
- Inputs/outputs remain in that browser session's server-side memory. Files are removed from the UI's selected input state after successful processing; results remain until reset/expiry. Native widget/framework buffers may exist for the session lifetime.
- Cancel/New Test clears session state and changes widget keys. With an active page, a 60-second timer clears media/results after 15 minutes of inactivity. Closing or disconnecting a browser does not guarantee immediate deletion of Streamlit's internal buffers; stop the service to remove process memory. This is a local prototype, not a certified secure-erasure implementation.
- API working directories are OS-generated `strokesense-*` temporary directories, mode 0700, with files mode 0600 on Ubuntu. They are removed on normal success and handled exceptions. Multipart handles are closed. API responses use `Cache-Control: no-store`.
- A hard crash/power loss can leave OS temp files. On a dedicated deployment, administrators must schedule deletion of **only stale StrokeSense temp directories belonging to the service user after ensuring no requests are running**. This cleanup policy is not a background service in this release. Do not deploy multi-user until that operations policy is configured.
- Do not log multipart bodies, authorization tokens, model input files or full inference results. Access logging is disabled by the launcher. Native ML libraries may log initialization/warnings, but no capture contents are intentionally logged.
- Authentication uses an ephemeral backend bearer token, generated by the launcher and held in environment memory. Both services bind to loopback. Any person with access to the same OS account/browser may still access that local session. This is not multi-user access control.
- Repository Data datasets and explicit evaluation outputs are developer-managed references, separate from webcam-user captures; they are not automatically deleted. They are excluded from commits.
- HTTPS and user authentication are mandatory for any future network deployment. They have not been provisioned here. Research consent forms, ethics approval, withdrawal handling and retention schedules must be designed before enabling research collection.
